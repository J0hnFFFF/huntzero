# 流程总控

自动推进阶段、路由任务、汇总结果。

## 执行流程

```
开始
  ↓
Phase 1: 信息收集
  ├─ 历史参考
  └─ 代码理解
  ↓
Phase 2: 目标定义
  └─ 明确反制目标
  ↓
Phase 3: 深度挖掘
  ├─ 角度 A：输入处理
  ├─ 角度 B：数据解析
  ├─ 角度 C：文件操作
  └─ 角度 D：配置依赖
  ↓
Phase 4: 假设验证
  └─ 过滤假阳性
  ↓
Phase 5: 利用链构建
  └─ 构建完整利用链
  ↓
Phase 6: 评估验证
  └─ 通用性/稳定性/实战价值
  ↓
Phase 7: 变体分析
  └─ 挖掘同类变体
  ↓
Phase 8: 方案生成
  └─ 生成利用方案
  ↓
Phase 9: 报告生成
  └─ 输出最终报告
  ↓
完成
```

## 阶段控制

### 回溯机制

```
发现问题？
├─ 是 → 继续下一阶段
└─ 否 → 回溯
         ├─ 切换分析角度
         ├─ 深入逻辑层面
         └─ 切换开发者视角
```

### 质量门控

每个阶段完成后检查：

| 阶段 | 质量门控 |
|------|----------|
| Phase 1 | 架构清晰、关注点识别完整 |
| Phase 2 | 目标明确、优先级合理 |
| Phase 3 | 每个角度都有深入分析 |
| Phase 4 | 假阳性过滤完成 |
| Phase 5 | 利用链完整可达 |
| Phase 6 | 评估全面客观 |
| Phase 7 | 变体搜索穷尽 |
| Phase 8 | 方案可验证运行 |
| Phase 9 | 报告专业完整 |

## 多角度分析策略

| 角度 | 焦点 | 目标 |
|------|------|------|
| A | 输入处理 | 数据接收、参数处理 |
| B | 数据解析 | 协议解析、格式处理 |
| C | 文件操作 | 路径处理、读写操作 |
| D | 配置依赖 | 默认配置、第三方组件 |

## 用户交互点

在以下节点询问用户：
1. Phase 1 完成后：确认理解是否准确
2. Phase 3 完成后：确认是否需要调整方向
3. Phase 6 完成后：确认评估结果
4. Phase 9 完成后：确认报告是否满足需求

## 使用方式

### 一键启动
```
开始挖掘
```

### 继续上次
```
继续上次流程
```

### 指定阶段
```
从 Phase 3 开始
```

## 输出

最终产出：
- 完整分析报告
- 利用方案代码
- 验证证据
