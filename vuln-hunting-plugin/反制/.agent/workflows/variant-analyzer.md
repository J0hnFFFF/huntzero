# 变体分析

系统性挖掘已发现问题的同类变体。

## 为什么做变体分析

- 一个问题往往不是孤立的
- 开发者可能在多处犯同样的错误
- 变体可能有更好的利用条件
- 即使主问题被修复，变体可能遗漏

## 变体类型

### 同位置变体
- 同一函数的其他代码路径
- 同一模块的其他函数
- 相似功能的平行实现

### 同模式变体
- 代码库中其他位置的相同模式
- 同样的问题在不同上下文

### 同依赖变体
- 使用同一组件的其他地方
- 相同处理逻辑的其他功能

### 跨版本变体
- 历史版本中的相同问题
- 新版本中的回归

## 变体挖掘方法

1. **提取模式**：从已发现的问题中提取模式
2. **全局搜索**：在整个代码库中搜索类似模式
3. **上下文分析**：理解问题根因，寻找同根因的其他表现
4. **开发者习惯**：同一开发者的其他代码是否有类似问题

## 输出格式

```
## 变体分析报告

### 原始问题
- 位置: [位置]
- 模式: [模式描述]
- 根因: [根本原因]

### 搜索模式
1. [模式1]
2. [模式2]

### 发现的变体

#### 变体 #1
- 类型: [类型]
- 位置: [位置]
- 与原问题差异: [描述]
- 利用条件: [是否更好]
- 优先级: [高/中/低]

### 变体汇总
| # | 位置 | 类型 | 利用条件 | 优先级 |
|---|------|------|----------|--------|
```
