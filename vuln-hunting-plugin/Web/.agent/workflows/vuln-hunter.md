# Web 漏洞挖掘 (Web Vuln Hunter)

专注于 Web 应用的业务逻辑、数据流向及安全模型分析。

## 分析角度

### 1. 输入信任边界
- 用户输入进入核心逻辑的路径
- 框架层面的过滤与转义机制
- 二次处理（存储后读取）的数据流

### 2. 业务逻辑完整性
- 状态机流转（订单/支付/审批）
- 关键操作的前置条件检查
- 多步流程的上下文一致性

### 3. 认证与授权模型
- 身份识别凭证的生命周期
- 垂直（角色）与水平（对象）权限控制
- 跨域/跨服务的信任关系

### 4. 组件与架构安全
- 依赖组件的已知缺陷
- 配置文件的安全基线
- 序列化/反序列化机制
- **⚠️ 可扩展机制风险**: 插件系统、适配器架构、主题引擎等可能被劫持
  - 检查 `content/adapters/` 或类似用户可写目录
  - 分析适配器/插件加载优先级和验证机制
  - 检查是否能通过文件写入劫持系统组件

## 挖掘方法论

### 逻辑流映射
构建业务逻辑图，识别非预期路径：
- 绘制正常业务流程图
- 寻找流程中的断点、跳跃点和循环点
- 尝试逆向或乱序执行流程步骤

### 启发式探测
基于经验规则的智能化探测：
- 识别参数类型与语义 (ID/URL/File/Code)
- 根据语义选择对应的 Mutator (变异器)
- 观察响应差异 (Diffing) 推断内部逻辑

### 污点追踪 (Taint Analysis)
静态或动态追踪数据流：
- 标记不可信输入源 (Source)
- 监控敏感操作汇聚点 (Sink)
- 分析中间净化过程 (Sanitizer) 的有效性
- **⚠️ 跨组件追踪**: 数据流可能跨越多个文件/组件，必须追踪完整路径 (参考 Ghost 导入案例)
