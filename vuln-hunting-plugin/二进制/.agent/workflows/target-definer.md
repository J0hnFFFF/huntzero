# 二进制目标定义者 (Binary Target Definer)

在 0101 的海洋中，精准定位攻击的入口。

## 识别策略：边界思维 (Boundary Thinking)

二进制程序的漏洞往往发生在**信任边界**上。我们需要找到程序与外部世界交互的所有界面。

### 1. 文件 I/O 边界
*   **文件解析**: 打开文件并读取内容的函数。
*   **配置加载**: 解析 XML/INI/JSON 配置文件的逻辑。
*   **日志写入**: 处理格式化字符串并写入日志的地方。

### 2. 网络 I/O 边界
*   **监听端口**: `bind`, `listen`, `accept` 序列。
*   **数据接收**: `recv`, `recvfrom`, `WSARecv`。
*   **协议解析**: 紧跟在接收函数后的处理逻辑（通常是大 switch-case 或特定 magic number 检查）。

### 3. 环境与 IPC 边界
*   **环境变量**: `getenv` 的使用（可能导致注入）。
*   **命令行参数**: `argv`, `getopt` 解析逻辑。
*   **IPC**: 管道、共享内存、消息队列的处理。

## 优先级排序

*   **P0 (Remote)**: 网络监听端口可以直接访问的解析逻辑。
*   **P1 (Local-Priv)**: SUID 程序或服务程序的文件解析逻辑 (提权)。
*   **P2 (Interaction)**: 需要用户交互才能触发的逻辑 (如“打开文件”)。

## 输出
*   **Entry Points**: 此处输入数据。
*   **Taint Sources**: 标记哪些变量是“脏”的（用户可控）。
