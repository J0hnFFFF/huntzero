## 详细流程步骤

### 阶段 1: 漏洞挖掘 (Discovery)

**目标**: 发现可利用的 0day/1day 漏洞

**步骤**:
1. **AI 自动化**
   - Cerebrum 解析目标（邮件服务、Web 应用、Agent 系统）
   - Drone 执行模糊测试（AFL++/libFuzzer）
   - Blackboard 记录假设树和置信度
   - 初始分类标签：`email`, `web`, `countermeasure`, `agent`

2. **人类专家介入点** ✋
   - 审核目标范围和授权边界
   - 确认高价值目标优先级
   - 决策是否深入某个漏洞方向

3. **决策点**: 漏洞假设是否有效？
   - **是** → 进入阶段 2
   - **否** → ❌ 终止任务

**输出**:
- 漏洞假设列表（CVE-ID 或 zeroday-XXXX）
- 初步分类标签和置信度评分
- 攻击面分析报告

---

### 阶段 2: 目标部署 (Deployment)

**目标**: 在隔离环境中复现目标系统

**步骤**:
1. **AI 自动化**
   - 自动生成 Docker Compose 配置
   - 拉取目标版本（从漏洞报告或官方镜像）
   - 配置网络隔离（防止外泄）
   - 部署监控探针（进程监控、网络抓包）

2. **人类专家介入点** ✋
   - 审核部署配置（确保隔离）
   - 提供特殊依赖或许可证
   - 确认环境匹配生产环境

3. **决策点**: 目标环境是否就绪？
   - **是** → 进入阶段 3
   - **否** → 🔄 返回重新部署

**输出**:
- 可访问的目标环境（HTTP/SSH/API）
- 环境指纹（版本、配置、补丁状态）
- 监控日志通道

---

### 阶段 3: 漏洞验证 (Verification Loop) ⭐ 核心阶段

**目标**: 确认漏洞存在且可利用

**步骤**:
1. **AI 自动化（循环执行，最多 10 次）**
   ```
   循环开始
     ├─ Drone 生成 PoC（基于漏洞假设）
     ├─ 在隔离环境执行 PoC
     ├─ 解析执行结果
     │   ├─ 成功 → 记录利用路径，跳出循环
     │   ├─ 失败 → 分析失败原因（语法错误/逻辑错误/环境不匹配）
     │   └─ 超时 → 调整超时阈值，重试
     ├─ 自动修复 PoC（语法修复、参数调整）
     └─ 更新 Blackboard 置信度
   循环结束
   ```

2. **人类专家介入点** 🔒 **强制审核**
   - 审核 PoC 生成后，审核利用逻辑
   - 验证失败超过 3 次，人工分析根因
   - 决策是否放弃该漏洞

3. **决策点 1**: 验证是否通过？
   - **是** → 进入阶段 4
   - **否** → 继续循环 或 进入决策点 2

4. **决策点 2**: 失败是否超过 3 次？
   - **是** → 人工介入分析
   - **否** → 🔄 修复 & 重试

5. **决策点 3**: 是否放弃？
   - **是** → 🔄 返回阶段 1 重新挖掘
   - **否** → 继续循环

**输出**:
- 验证通过的 PoC（可执行、可复现）
- 利用条件清单（需要的权限、网络位置、用户交互）
- 失败原因分析报告（如果验证失败）

---

### 阶段 4: 利用链设计 (Chain Design)

**目标**: 将单个漏洞组合成完整攻击链

**步骤**:
1. **AI 自动化**
   - 分析利用前置条件（初始访问方式、所需权限）
   - 搜索可组合的漏洞（0day + Nday 组合）
   - 生成多套链条方案：
     - **链条 A**: 单一 0day（隐蔽性强）
     - **链条 B**: 0day + Nday 组合（成功率高）
     - **链条 C**: 多漏洞链（适用复杂场景）
   - 评估链条复杂度与风险

2. **人类专家介入点** 🎯 **战略决策**
   - 选择哪个链条方案
   - 考虑 OPSEC（是否留痕、是否可被防御者溯源）
   - 决策是否引入 Nday（可能被 IDS/IPS 检测）

3. **决策点**: 链条设计是否通过？
   - **是** → 进入阶段 5
   - **否** → 🔄 重新设计

**输出**:
- 攻击链条设计文档（包含每个步骤）
- 所需漏洞列表（已验证的 PoC）
- 预期效果和风险分析

---

### 阶段 5: ATT&CK 映射 (Attack Planning)

**目标**: 将攻击链条映射到 MITRE ATT&CK 框架

**步骤**:
1. **AI 自动化**
   - 为每个链条步骤分配 ATT&CK 技术 ID
     - 初始访问: T1566.001 (Spearphishing Attachment)
     - 执行: T1203 (Exploitation for Client Execution)
     - 持久化: T1136 (Create Local Account)
     - 防御规避: T1140 (Deobfuscate/Decode Files)
     - C2: T1071.001 (Web Protocols)
   - 生成攻击路径图（从初始访问到数据外传）
   - 识别可能被检测的关键节点

2. **人类专家介入点** ✋
   - 审核 ATT&CK 映射准确性
   - 决策是否替换易被检测的技术
   - 设计防御规避策略（混淆、免杀、流量伪装）

3. **决策点**: 风险是否可控？
   - **是** → 进入阶段 6
   - **否** → 🔄 重新设计

**输出**:
- ATT&CK 映射表（技术 ID + 实施方法）
- 防御规避方案（反沙箱、反调试、反内存取证）
- 检测风险评估（哪些步骤可能被 EDR/SIEM 发现）

---

### 阶段 6: 武器化与部署 (Weaponization & Deploy)

**目标**: 构建可交付的武器平台

**步骤**:
1. **AI 自动化**
   - **场景 1: 邮件类**
     - 生成恶意文档（Word/Excel/PDF）
     - 嵌入漏洞利用代码
     - 绕过邮件网关检测（编码混淆）
     
   - **场景 2: 反制类**
     - 构建 C2 服务器（兼容 Cobalt Strike/MSF）
     - 生成 payload（多格式：exe/script/macro）
     - 自毁机制（使用后清除痕迹）
     
   - **场景 3: Web 类**
     - 构建 Webshell（加密通信）
     - 权限提升模块（内核漏洞利用）
     - 横向移动工具（Pass-the-Hash）
     
   - **场景 4: Agent 类**
     - 构建 AI Agent 攻击链（提示注入 → 代码执行）
     - 生成对抗样本（绕过 LLM 安全策略）

2. **人类专家介入点** 🔒 **最终审核**
   - 审核武器化方案是否符合 OPSEC 要求
   - 测试部署环境（是否触发目标防御）
   - 决策是否添加诱饵/混淆

3. **决策点**: 审核是否通过？
   - **是** → ✅ **武器交付**
   - **否** → 🔄 修改方案

**输出**:
- 武器化平台（可执行文件/脚本/文档）
- 使用说明（部署步骤、参数配置）
- OPSEC 检查清单（避免暴露身份）

## 循环与异常处理

### 验证循环（阶段 3）

```
┌─────────────────────────────────────────────────────────────┐
│  尝试次数 | AI 动作                    | 人类介入          │
├─────────────────────────────────────────────────────────────┤
│  1-3     | 自动生成并修复 PoC        | 审核 PoC 逻辑     │
│  4-6     | 调整利用路径              | 分析失败根因      │
│  7-10    | 引入替代漏洞             | 决策是否放弃      │
│  >10     | 标记为"验证失败"          | 归档并重新评估    │
└─────────────────────────────────────────────────────────────┘
```

### 链条迭代（阶段 4-5）

- 如果实战测试失败 → 返回阶段 3 补充验证
- 如果被防御者检测 → 返回阶段 5 重新设计规避方案
- 如果 OPSEC 风险过高 → 返回阶段 4 重新设计链条

## OPSEC 与安全检查

### 关键原则

1. **隔离优先**: 所有测试在隔离环境进行
2. **最小暴露**: 武器化代码不包含开发者指纹
3. **可控销毁**: 所有武器平台支持自毁
4. **合规审计**: 每次使用记录用途和结果

### 禁止行为

- ❌ 在未授权系统测试
- ❌ 保留后门用于非授权访问
- ❌ 泄露武器化代码给第三方
