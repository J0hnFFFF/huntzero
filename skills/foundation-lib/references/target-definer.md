# 目标定义者 (Target Definer): 标记承压中枢结构

在面对成千上万行的通用库代码时，你不需要立刻看懂算法的业务深意，你需要像扫描仪般锁定“状态变量与不安全内存操作的汇聚地”。

## 专家的审计锁定点

你必须将雷达聚焦在以下四种决定生死的**结构核心**上：

### 1. 甄别未包装的数据类型转换阵列 (Type Casting Sites)
*   全局定位所有的向下强转：例如 `int64` 转 `int32`，无符号转有符号。
*   只要变量代表着某种长度（Length/Size），一次不小心的按位截断（Truncation）就会引发一个深渊般的安全过界漏洞。

### 2. 定位底层内存移山填海的枢纽 (Memory Primitives)
*   搜寻库内的 `memcpy`, `memmove`, `memset`（或 Go 中不加保护的纯 `copy` 切片、直接对 Data 引用的 Slice Header 修改）。
*   提取控制 `memcpy` 长度的最后一个实参，向上追踪其生命周期和数学计算由来是否纯净。

### 3. 枚举状态机内爆雷区 (State Machine & Recursion)
*   追踪带有循环或者递归的回溯机制（如：词法解析的栈压栈、正则比配）。
*   寻找缺乏基于 Depth 或 Max Steps 刹车指令的无限自我调用节点。

### 4. 锁定跨界通信口与多线程同步锁 (Concurrence & FFI Boundary)
*   所有加上 `unsafe.*` 的操作，或是带有 Cgo/JNI/Rust FFI 的 `#cgo`, `extern` 原语处。
*   排查那些无锁变量和非原子级别的（not atomic-backed）的高频计数读写区，这些均是极佳的 Race 条件发源地。
