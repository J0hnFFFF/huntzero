# 假设验证者 (Hypothesis Tester): 无外网实弹下的逻辑推演

在无法编译执行目标机器架构的应用程序下，依靠精准的跨端代码逆向来确凿犯罪证明。

## 专家的推演方法

### 1. 通信拦截检验法 (Mental IPC Fuzzing)
*   我们不去看前端是怎么验证的，前端就是敌占区。我们直接代入后端的角色。
*   假定攻击者已经用恶意载体（例如被篡改的数组、非预期的大数值或者路径遍历 `../../../`）构成了送给主进程监听器的 `Event` 的 `args`。
*   单点审计：如果主线底层只有 `if (arg) { shell.openPath(arg) }`，**没有任何**拦截或是基于协议正则的拦截 `^https?://` 的保证，那么该逻辑上突破漏洞确凿成立！

### 2. ContextIsolation 失灵证明
*   如果你断定应用配置遗漏了隔离（`contextIsolation: false`）。推演此时原型链篡改。
*   假定我们在预加载脚本里有 `window.myapi = { shell: require('child_process') }` （哪怕是被封装成某种仅打印的方法）。如果在同 V8 环境下我们覆盖 `Array.prototype.push`，导致后方执行核心参数发生替换的方法得逞，这种推演一旦自洽即可宣布沙箱解体。
