# Web 目标定义者 (Web Target Definer)

基于 SKILL.md 的四大地形，识别最具结构性风险的业务端点。

## 地形一：单次请求的不可逆操作点

**本质特征**：一旦执行，无法回滚的状态转换。

**识别标准**：
- 资金动账：转账、支付、退款、提现
- 权限变更：角色授予、API Key 生成、密码修改
- 数据销毁：账户删除、记录清空、退订服务
- 关键配置：域名绑定、安全策略变更、审计日志清除

**价值评估**：
- 是否存在**预执行确认**？能否被绕过？
- 是否可被**跨域诱导**执行？
- 是否允许**并发/重放**造成累积效应？

## 地形二：状态推断的断层带

**本质特征**：服务器从请求参数推断业务状态，而非查询实际状态。

**识别标准**：
- 资源标识：URL 中的 `/{resource_id}`、Body 中的 `id` 字段
- 流程状态：`status=completed`、`step=3` 等客户端声明的状态
- 权限标记：`is_admin=true`、`role=owner` 等客户端声明的权限
- 时间戳/序列号：客户端提供的 `timestamp`、`nonce`

**价值评估**：
- 推断的来源是否完全可控？
- 推断结果是否与实际数据库状态交叉验证？
- 并发请求下的推断是否可能冲突？

## 地形三：信任链的重构节点

**本质特征**：跨域/跨站点交互中，信任边界被重新协商。

**识别标准**：
- OAuth 流程：`/oauth/callback`、`/auth/redirect`
- 跨域通信：`postMessage` 监听、SharedWorker、BroadcastChannel
- 第三方嵌入：Analytics、Payment Widget、Social Login
- 跨域资源：CORS 端点、JSONP 接口、字体/图片跨域加载
- 跳转出口：`next_url`、`return_to`、`redirect_uri` 参数

**价值评估**：
- 目标 Origin 的验证严格性？
- 能否将信任重定向到攻击者控制域？
- 跨域响应是否携带敏感凭证？

## 地形四：语义转换的扭曲点

**本质特征**：输入文本在多层处理中被不同解释。

**识别标准**：
- 文件操作：上传路径、导入文件名、ZIP 解压目标
- 路由解析：URL Path、参数路由匹配
- 数据解析：JSON/XML/YAML 解析后的类型转换
- 编码处理：URL decode、Base64、Unicode 规范化
- 长度限制：字符数 vs 字节数、显示长度 vs 存储长度

**价值评估**：
- 安全层基于什么解释做判断？
- 执行层实际使用什么解释？
- 两层解释是否存在差异可被利用？

## 优先级排序（基于风险本质，非漏洞类型）

**P0 - 结构性信任崩塌**：
- 单次不可逆操作 + 可被跨域诱导（意志不确定 × 信任重构）
- 状态推断完全可控 + 涉及资金/权限（失忆困境 + 高价值目标）

**P1 - 状态推断失效**：
- 资源 ID 推断断层 + 影响其他用户数据
- 流程状态可伪造 + 绕过业务限制

**P2 - 语义解释差异**：
- 路径/文件名语义断层 + 可导致文件系统越界
- 类型混淆 + 可导致权限提升

**P3 - 信息泄露辅助**：
- 可推断内部状态（用户存在性、资源数量）
- 可观察处理差异（时间、响应长度）

## 输出

- **Attack Surface Map**: 标注四大地形的高风险端点分布
- **Inference Chain Analysis**: 每个 P0/P1 端点的状态推断链分析
- **Cross-Origin Trust Flow**: 信任重构节点的信任流向图
