# Web 评估验证 (Web Validator)

验证假设的结构性脆弱是否真实存在，而非验证具体漏洞类型。

## 验证框架（与四大原理对齐）

### 验证原理一：意志不确定性
**核心问题**：能否在不触发用户主动确认的情况下，诱导执行不可逆操作？

**验证方法**：
- 跨域诱导测试：从攻击者域名构造请求，观察是否携带用户凭证被执行
- 预检绕过测试：是否存在可跳过的确认步骤（直接 POST 而非表单提交）
- 凭证解耦测试：移除/篡改身份凭证后，操作是否仍被接受

**关键指标**：
- 是否存在 SameSite=Strict Cookie？
- 是否验证 Origin/Referer？
- 关键操作是否要求重新认证或二次确认？

### 验证原理二：失忆困境
**核心问题**：服务器是否会基于请求中的"声称状态"而非实际状态执行操作？

**验证方法**：
- 资源所有权测试：修改 resource_id 为其他用户资源，观察是否被拒绝
- 状态伪造测试：在流程未完成时，直接发送"已完成"状态的请求
- 并发冲突测试：同时发送两个修改同一资源的请求，观察状态一致性
- 凭证时效测试：使用过期 Token、已禁用账户发起请求

**关键指标**：
- 服务器是否查询数据库验证所有权？
- 是否验证前置状态已完成？
- 并发请求下的状态是否最终一致？

### 验证原理三：信任重构
**核心问题**：跨域信任边界是否真的限制了攻击者？

**验证方法**：
- Origin 绕过测试：篡改 Origin Header，观察 CORS 响应变化
- 跳转劫持测试：修改 `redirect_uri`/`next` 参数到攻击者域名
- postMessage 注入：从攻击者页面发送消息，观察是否被接收
- 子域名探测：检查是否存在指向可被接管服务的 CNAME

**关键指标**：
- CORS 配置是否允许攻击者 Origin？
- 跳转参数是否严格校验域名白名单？
- postMessage 是否验证 `event.origin`？

### 验证原理四：语义断层
**核心问题**：安全层与执行层对输入的解释是否存在可被利用的差异？

**验证方法**：
- 编码差异测试：同一 payload 使用不同编码（URL、Unicode、HTML 实体）
- 类型混淆测试：传入数字 `0` vs 字符串 `"0"`，数组 vs 单值
- 长度差异测试：多字节字符、组合字符、零宽度字符
- 规范化差异测试：`..%c0%af..` vs `../..`

**关键指标**：
- 安全层拒绝但执行层接受？
- 不同编码导致不同处理结果？
- 长度计算在各层是否一致？

## 无害化验证原则

**不破坏、不泄露、可观测**

- **时间盲测**：使用延迟响应而非数据提取（验证 SQL 注入、命令执行）
- **逻辑探测**：构造特定条件观察响应差异（验证状态推断）
- **只读越权**：尝试读取非敏感数据验证权限边界（验证 IDOR）
- **DNSLog**：外带验证（验证 SSRF、命令执行）

## 响应差异分析（推断服务器内部逻辑）

**状态码差异**：
- 200 vs 403：权限检查是否存在？
- 403 vs 404：是否能区分"存在但无权" vs "不存在"？
- 500 vs 400：错误类型是否泄露内部逻辑？

**响应内容差异**：
- 长度变化：是否包含额外的错误信息？
- 时间差异：是否存在可观测的处理延迟？
- 结构差异：JSON/XML 返回的字段是否变化？

**推断目标**：
从差异反推服务器的内部处理流程 —— "什么条件下服务器会走这条分支？"
