# Web 验证器 (Validator): 五维度定损：从业务漏洞到系统性风险

> Web 漏洞的严重性不是 CVSS 说了算的，是业务场景说了算的。
> 一个 CSRF 在博客系统上是 Low，在银行转账接口上是 Critical。
> 你的任务是：根据项目类型和业务场景，给出让 CTO 睡不着的定损。

## 定损框架：Web 漏洞的五个破坏维度

### 维度一：横向移动能力（Lateral Movement）

**核心问题**：从一个被攻破的端点，能到达多少其他端点/用户/数据？

| 场景 | 横向移动范围 | 评级 |
|------|------------|------|
| 单一 IDOR，只能读取单个资源 | 限于该资源 | Low |
| 可遍历 ID，批量读取所有用户数据 | 全平台用户数据 | Critical |
| CSRF 触发转账，但仅影响当前用户 | 单个用户账户 | Medium |
| OAuth redirect_uri 劫持，可绑定任意用户账号 | 所有使用该 OAuth 的用户 | Critical |
| 管理员接口的 IDOR | 所有用户数据 + 系统配置 | Critical |
| GraphQL 内省查询暴露所有 schema | 所有 API 端点暴露 | High |

### 维度二：业务影响深度（Business Impact）

**核心问题**：这个漏洞直接造成什么业务损失？

| 影响类型 | 描述 | 典型场景 |
|---------|------|---------|
| 资金损失 | 直接转账、退款、提现 | 支付接口 CSRF、价格篡改 |
| 数据泄露 | 用户 PII、订单、聊天记录 | IDOR、GraphQL 越权 |
| 权限提升 | 普通用户变管理员 | 状态伪造、JWT 篡改 |
| 服务破坏 | 删除数据、篡改配置 | 批量删除 IDOR、管理员接口 |
| 声誉损害 | 账号被绑定到攻击者 | OAuth 劫持、SSRF 发送钓鱼邮件 |
| 合规风险 | GDPR、PCI-DSS 违规 | 大规模数据泄露 |

**项目类型校准**：
- 高价值交易类（金融、电商）：资金损失 = P0
- 多租户 SaaS：数据隔离失效 = P0
- 社交平台：账号劫持 = P0
- 内部工具：信息泄露 = P1-P2

### 维度三：利用门槛（Exploitation Barrier）

**核心问题**：攻击者利用这个漏洞需要多少成本？

| 门槛 | 描述 | 评级调整 |
|------|------|---------|
| 0-Click | 用户无需任何操作，攻击自动发生 | +1 severity |
| 1-Click | 用户只需点击一个链接或访问一个页面 | 不变 |
| 需登录 | 需要用户已登录目标系统 | -0.5 |
| 需社工 | 需要钓鱼邮件、XSS 等前置攻击 | -1 |
| 需内部权限 | 需要管理员或内部员工配合 | -1.5 |

### 维度四：检测与响应难度（Detection & Response）

**核心问题**：这个漏洞被利用后，防守方能否及时发现和修复？

| 难度 | 描述 | 评级调整 |
|------|------|---------|
| 极难检测 | 利用后无异常日志，与正常请求无法区分 | +1 |
| 难以检测 | 日志中有记录，但混杂在正常流量中 | +0.5 |
| 中等 | 有明确异常指标（金额异常、权限变更） | 不变 |
| 容易检测 | 产生明显错误、告警或用户投诉 | -0.5 |

### 维度五：修复成本与范围（Remediation Cost）

**核心问题**：修复这个漏洞需要改多少代码？影响多少功能？

| 成本 | 描述 | 评级调整 |
|------|------|---------|
| 单点修复 | 修改一个函数/端点即可 | -0.5 |
| 多点修复 | 需要在多个 Controller/Service 中添加校验 | 不变 |
| 架构级修复 | 需要重构权限模型、状态机或中间件顺序 | +0.5 |
| 全平台修复 | 需要修改所有 API、前端、移动端 | +1 |
| 第三方依赖 | 需要升级框架或等待供应商修复 | +1 |

## 专家评估标准

### 场景一：银行转账接口 CSRF

**漏洞**：`POST /api/transfer` 无 CSRF 保护，SameSite=None，Cookie 认证。

**五维度评估**：
- 横向移动：单个用户账户资金 → **Medium**
- 业务影响：直接资金损失 → **Critical**
- 利用门槛：1-Click（诱导访问恶意页面）→ **Low 门槛**（+1）
- 检测难度：转账记录存在但可能延迟发现 → **Medium**
- 修复成本：添加 CSRF Token + SameSite 配置 → **单点修复**（-0.5）

**综合定损**：**Critical / P0**

**威慑声明**：
> 攻击者只需让已登录用户访问一个恶意网页，即可在用户完全无感知的情况下将其账户资金转走。
> 由于浏览器自动携带 Cookie，服务器无法区分这是用户主动操作还是攻击者诱导。
> 这不是"可能出问题"，是"今天就可以被大规模利用"。

### 场景二：电商订单 IDOR

**漏洞**：`GET /api/orders/{id}` 未绑定 user_id，可遍历所有订单。

**五维度评估**：
- 横向移动：全平台所有用户的订单详情 → **Critical**
- 业务影响：大规模 PII 泄露（地址、电话、购买记录）→ **Critical**
- 利用门槛：仅需登录（低门槛）→ **Low 门槛**
- 检测难度：日志中显示正常 API 访问，难以区分恶意遍历 → **极难检测**（+1）
- 修复成本：需要在所有订单相关查询中添加 user_id 条件 → **多点修复**

**综合定损**：**Critical / P0**

### 场景三：OAuth redirect_uri 前缀匹配

**漏洞**：`redirect_uri` 校验使用 `startsWith("https://victim.com/")`。

**五维度评估**：
- 横向移动：所有使用该 OAuth 登录的用户 → **Critical**
- 业务影响：账号被绑定到攻击者，可长期控制 → **High**
- 利用门槛：需诱导用户点击链接 → **1-Click**
- 检测难度：OAuth 流程看起来正常，用户可能数周后发现异常 → **极难检测**（+1）
- 修复成本：修改 redirect_uri 校验为精确匹配 → **单点修复**（-0.5）

**综合定损**：**Critical / P0**

### 场景四：文件上传路径穿越

**漏洞**：上传文件名 `"../../../app/config.py\x00.jpg"` 可覆盖配置文件。

**五维度评估**：
- 横向移动：影响整个应用，可能导致 RCE → **Critical**
- 业务影响：应用配置被篡改，可能导致全面沦陷 → **Critical**
- 利用门槛：需要文件上传功能可用 → **1-Click**
- 检测难度：上传日志可能记录原始文件名，但实际写入路径不同 → **难以检测**（+0.5）
- 修复成本：路径规范化 + 白名单 → **单点修复**（-0.5）

**综合定损**：**Critical / P0**
