# Web 变体分析 (Web Variant Analyzer)

识别结构性假设在代码库中的重复模式，发现系统性脆弱。

## 核心概念

**变体的本质**：同一结构性假设被打破的模式，在不同场景下的重复出现。

不是寻找"相似的漏洞"，而是寻找"相同的推断错误"。

## 分析维度（原理驱动）

### 1. 推断链同构（原理二：失忆困境）

**识别模式**：
```
模式：参数 → 直接查询 → 操作（无所有权验证）

变体A：
GET /user/{id}/profile → UserDao.findById(id) → 返回数据

变体B：
GET /order/{orderId}/detail → OrderDao.findById(orderId) → 返回数据

变体C：
POST /api/document/{docId}/share → DocumentService.share(docId) → 执行分享

共同假设断裂点：服务器假设请求中的ID即用户有权访问的资源
```

**分析方法**：
- 扫描所有接收资源ID作为参数的端点
- 检查是否都遵循相同的推断链模式
- 验证是否都存在相同的验证缺失

### 2. 信任边界复用（原理三：信任重构）

**识别模式**：
```
模式：统一的跨域配置/跳转处理

变体A：OAuth 回调 → redirect_uri 验证
变体B：登录后跳转 → next 参数验证
变体C：支付完成 → return_url 参数验证

共同假设断裂点：统一的验证逻辑可能存在相同绕过方式
```

**分析方法**：
- 识别所有跨域交互点
- 检查是否使用相同的验证工具/方法
- 验证绕过方式是否可复用

### 3. 语义转换一致性（原理四：语义断层）

**识别模式**：
```
模式：同一处理流程在多处复制

变体A：文件上传 → 安全检查A → 保存操作B
变体B：头像上传 → 安全检查A → 保存操作B
变体C：导入功能 → 安全检查A → 解析操作C

共同假设断裂点：安全检查与实际执行的解释差异
```

**分析方法**：
- 识别 Copy-Paste 的安全检查代码
- 检查各变体中执行层是否一致
- 验证编码/类型转换在各变体中是否相同

### 4. 意志确认缺失模式（原理一：意志不确定性）

**识别模式**：
```
模式：关键操作缺乏统一确认机制

变体A：删除账户 → 无二次确认
变体B：修改邮箱 → 无验证邮件
变体C：API Key 生成 → 无明确提示

共同假设断裂点：系统假设用户明确知道自己在做什么
```

**分析方法**：
- 识别所有不可逆操作端点
- 检查是否都缺乏后端确认
- 验证跨域诱导在各端点的成功率

## 分析方法

### 语义聚类（推断链层面）

**聚类维度**：
- **参数语义**：`id`、`resourceId`、`targetId` 等标识资源ID的参数
- **操作语义**：`get`、`view`、`update`、`delete` 等操作类型
- **验证模式**：相同的验证逻辑（或缺失）

**聚类目标**：
找到"参数 → 查询 → 操作"模式相同，但业务场景不同的端点组。

### 架构级假设审计

**审计对象**：
- **中间件假设**：网关层认为已经完成的验证（如身份认证）
- **框架假设**：框架提供的默认安全行为（如 CORS 配置）
- **库假设**：第三方库的内部假设（如解析器的边界检查）

**审计方法**：
- 检查架构文档与代码实现的一致性
- 验证各组件之间的信任边界
- 识别"假设其他组件已处理"的盲区

## 输出格式

```markdown
## 变体分析报告

### 核心假设模式
- 假设描述: [服务器做出的错误核心假设]
- 涉及原理: [意志不确定/失忆困境/信任重构/语义断层]
- 模式特征: [代码/逻辑层面的识别特征]

### 变体分布
#### 变体组 #1 - 推断链同构
- 端点列表: [URL1, URL2, URL3]
- 共同模式: [参数 → 查询 → 操作（无验证）]
- 验证状态: [已验证/待验证]

#### 变体组 #2 - 信任边界复用
- 组件列表: [OAuth, Login, Payment]
- 共同模式: [统一的重定向验证逻辑]
- 绕过方式: [已发现的绕过方法]

### 系统性影响
- 影响范围: [单个模块/全站/多服务]
- 根因分析: [为什么会出现这种模式]
- 修复建议: [结构性修复方向]
```

## 价值

- **效率提升**：验证一个推断链模式，可发现多处同类脆弱点
- **系统性修复**：修复共同根因，而非逐点修补
- **深度防御**：识别架构层面的假设盲区
