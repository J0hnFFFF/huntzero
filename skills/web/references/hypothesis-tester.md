# Web 假设验证 (Hypothesis Tester)

基于第一性原理，快速验证关于 Web 应用结构性行为的猜想。

## 验证目标（原理驱动）

### 验证意志不确定性假设
- 假设："这个端点可以在用户不知情的情况下被诱导执行"
- 验证：跨域请求是否携带凭证？是否触发确认？

### 验证失忆困境假设
- 假设："服务器依赖请求参数推断状态，而非查询实际状态"
- 验证：修改参数中的状态标记，观察服务器行为是否改变

### 验证信任重构假设
- 假设："跨域信任边界可以被重定向到攻击者控制域"
- 验证：篡改跳转参数、Origin、目标域名，观察信任是否被错误延伸

### 验证语义断层假设
- 假设："安全层与执行层对同一输入的解释存在差异"
- 验证：同一 payload 的不同编码/格式，是否导致不同处理结果

## 验证方法

### 1. 响应差异分析 (Response Diffing)
目的：从差异反推服务器内部处理逻辑

**观察维度**：
- 状态码变化：200 vs 403 vs 500 —— 哪层检查被触发？
- 响应时间：延迟差异是否泄露内部处理分支？
- 响应长度：错误信息是否泄露内部状态？
- DOM 结构：页面渲染是否反映不同的处理路径？

**分析逻辑**：
```
输入 A → 响应 X
输入 B → 响应 Y（与 X 不同）
↓
推断：服务器对 A 和 B 的处理路径不同
↓
进一步假设：差异点在何处？
```

### 2. 无害化探测 (Benign Probing)
原则：验证假设的存在性，而非完整利用

- **意志不确定**：构造跨域 GET 请求（而非 POST），观察预检行为
- **失忆困境**：修改资源 ID 为不存在值（而非其他用户资源），观察错误类型
- **信任重构**：尝试跳转到同源不同子域（而非攻击者域），观察白名单严格性
- **语义断层**：使用无害的编码差异（如大小写变化），观察处理一致性

### 3. 推断链验证
不验证漏洞是否存在，验证推断链是否断裂：

```
假设推断链：
请求参数 X → 服务器推断 Y → 执行 Z

验证方法：
1. 发送 X，观察是否执行 Z（确认链的存在）
2. 发送 X'（X 的变体），观察是否仍执行 Z（验证推断的严格性）
3. 发送 X''（恶意构造），观察是否执行 Z'（验证链的脆弱性）
```

```
### 验证设计
- 探测方法: [无害化测试方式]
- 预期差异: [如果假设成立，应观察到...]

### 观察结果

- 推断更新: [基于观察，修正后的理解]
```
