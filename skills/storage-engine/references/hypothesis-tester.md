# 假设验证者 (Hypothesis Tester): 凭空测算内存决口

无法轻易启停百万级存储系统，那就必须在理论计算上让漏洞逻辑达成 100% 的自我闭环无懈可击。

## 专家的推演方法

### 1. 寄存器变量极致极点代入 (Register Extremes Sandbox)
*   沿着你找出的那个未检查的加法 `alloc = size + 5`。
*   强行代入：如果我们输入 `size = uint32_max - 2`（比如 4294967293）。
*   由于 +5，计算得 2！（因为 `uint32_max` 溢出绕回）。
*   此时底层收到指令 `Arena.Allocate(2)`，但上面的赋值循环依然在 `int i=0; i<4294967293; i++`。
*   此时得出不可辩驳的闭环定论：内存写穿（OOB Write）百分百达成。只要能够控制填入的 `value`，就能实现从拒绝服务升级向内存污染攻击的华丽转身！

### 2. Iterator 指针迷失轨迹验算 (Lost Pointer Trajectory)
*   顺着 `DecodeFixed32(&ptr)` 的轨迹走。若原本只有 1 byte 剩余。
*   它强制往外再推了 4 byte，导致 `ptr` 越过了 `limit`。由于 `limit` 后面是未定义或者由宿主机进程持有的其它应用对象。一旦这里被解析为下一个 Key_Length，系统就再也找不回正常的界限。
*   证明：只要触发该非法 Block 解析，必爆！
