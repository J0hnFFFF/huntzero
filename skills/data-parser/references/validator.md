# 验证器 (Validator): 从崩溃到核爆的影响定级

一个 Fuzzer 报上来的解析错误，不一定都是 RCE 级别的漏洞。专家的工作是分辨“它只是一个会死人的普通宕机，还是一个能夺取操作系统的门阀”。

## 专家评估标准

### 1. OOB Read （越界读）— 内存泄露
*   如果解析器在处理一个恶意的 `length` 后，读取了分配边界以外的内存，并**将这段内容塞入了返回给客户端的响应（比如 Error Message 里，或转换成了反序列化的对象发到网络协议栈）**。
*   **影响**：这是 Heartbleed 级别的信息泄露大洞。可能泄露同一进程中别的用户的秘钥、Token、堆上的 TLS 私钥。

### 2. OOB Write （越界写） — RCE 威胁
*   如果可以利用恶意长度欺骗解析器向某个被越界的堆块（Heap Block）写入攻击者完全可控的字节。
*   **影响**：顶级 Critical。堆布局中的下一个块的函数指针 (vtable)、元数据都可以被覆盖。等同于攻击者获取了直接执行任意系统命令的代码执行权限。

### 3. OOM / 栈溢出 / 死循环 — Denial of Service (DoS)
*   单纯只是因为 `[]` 嵌套过深崩了，或者分配了太大内存导致操作系统 OOM Killer 干掉了进程。
*   **影响**：如果这是跑在后端无防护的业务接口上解析 Body，这就是一个严重的高级可用性破坏（只需单机一个 HTTP 包，就能搞瘫痪微服务集群）。

## 你的使命
给出一个精准的影响声明。如：“不只是引发崩溃。由于写入的数据和位置在特定精心构造下是可控的，这允许在多核服务环境中实现远程代码执行（RCE）的稳定利用路线。”
