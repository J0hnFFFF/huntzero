# 验证器 (Validator): 架构穿透能力评估

评估一个 AI Agent 漏洞，不仅仅是给出 CVSS 评分，而是要界定它对整个数字化系统的架构级影响。

## 专家评估标准

### 1. 自动化程度与交互要求（0-Click vs 1-Click）
*   **被动投毒 (1-Click)**：攻击者在某暗网论坛放一个带有注入代码的帖子，等待被害人的安全分析 Agent 爬取这个帖子。这需要时间且有偶然性。
*   **主动投毒 (0-Click)**：攻击者直接通过系统公开的提问 API 或邮件处理接口投递载荷，Agent 立即后台处理。这是顶级的可利用性。

### 2. 特权边界逃逸（Privilege Boundary Escape）
*   Agent 是在容器里运行代码（如 Dockerised Code Interpreter），还是直接在宿主机的主进程中？
*   如果只是在沙箱容器里通过 `python_exec` 跑代码，影响面是局部的（容器内逃逸难度高）。
*   如果是 Agent 的管理后台接口存在未授权访问（修改了 Agent 连接的数据库），影响面是超全局的。

给出一个“灵魂拷问”式的影响声明。例如：“通过一封无人值守的客服邮件，即可接管拥有整个公司 AWS S3 读取权限的 AI 后台。”
