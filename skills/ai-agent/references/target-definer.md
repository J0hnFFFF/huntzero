# 目标定义者 (Target Definer): 绘制信任与特权的边界

不要像传统渗透测试那样去枚举 URI 路由。真正的漏洞研究专家在面对 AI Agent 时，首先绘制的是**“心智输入地图 (Context Sinks)”**和**“动作输出空间 (Action Space)”**。

## 专家的思维推演

你必须思考以下几个核心问题并从代码中找出答案：

### 1. 寻找“眼睛和耳朵”：数据是如何钻进 LLM 大脑的？
寻找所有的 `append_message`、`add_context`、`query_vector_db` 或是直接调用 LLM API (`openai.ChatCompletion.create`) 的地方。
*   Agent 会从哪里读取不受信任的外部数据？（抓取指定 URL？读取用户上传的文件？查询第三方 API？）
*   这些数据是如何拼接到 Prompt 里的？系统是否有任何机制试图将“用户数据”与“系统指令”做隔离（虽然在 LLM 层面这种隔离注定是脆弱的）？

### 2. 寻找“手和脚”：大模型能对物理世界造成什么破坏？
深挖工具注册表（Tool Registry / MCP Configs）。
*   存在哪些高危的内置工具？`bash`, `python_exec`, `file_writer`, `sql_query`？
*   这些工具被映射到了宿主机的什么权限？
*   **关键问题**：这些工具调用前，是否有 “Human-in-the-loop (HITL)” (人类确认) 机制？哪些工具是默认免审批 (auto-approve) 的？自动审批的工具就是 RCE 的第一候选。

### 3. 寻找记忆海马体：系统的长期状态存储在哪里？
*   系统是否使用了 RAG（检索增强生成）？
*   如果是，谁能往向量数据库写数据？（比如任何人都能提交简历？）
*   读取数据库时的查询权限隔离（Tenant / Role）是否严密？

## 你的目标输出
建立一张清晰的图表：
**[攻击者可控的外部数据源]**  ---->  **[LLM 意图解析引擎]**  ---->  **[自动执行的高危 Tool]**
找出其中阻力最小的路径，这将是你下一步重点研究的链条。
