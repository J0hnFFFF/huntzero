## Go版误报率偏高根因分析

### 三大根因（代码级验证）

1. **Critic失败级联**：Go Critic超时/错误 → NEEDS_REVIEW → severity=none → 发现被拒 → 假设成孤儿 → sweepOrphaned在末尾晋升(无Critic审查)
   - Python Critic超时/错误 → ACCEPT → 发现至少经过了LLM审查
   - 关键代码：critic.go line 185-294 vs cerebrum.py line 2565-2642

2. **ExploitPrerequisites恒定true**：exploit/analyzer.go仅19行stub，NewExploitPrerequisites()返回IsSatisfiable=true
   - Python有exploit_analyzer.py(250行)：静态关键词+LLM推断，可判定IsSatisfiable=false
   - 效果：Go无法过滤"需要不可能的环境条件"的发现

3. **sweepOrphaned过度收割**：Layer2允许confidence>=0.75的假设直接晋升为发现，无需Drone/Critic确认
   - inferSeverityFromDescription默认medium → 弱发现也标为"中等"
   - 与根因1级联：Critic失败→发现被拒→假设孤儿→sweep晋升→绕过了Critic质量审查

### 修正方向
- Critic失败时应改为ACCEPT（与Python一致），或至少不让NEEDS_REVIEW触发发现拒绝
- 补全exploit/analyzer.go的双层分析逻辑
- sweepOrphaned Layer2门槛提升至0.85，或要求至少1个confirmed证据标签
