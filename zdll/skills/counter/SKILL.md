# 客户端程序地形情报 (Client-Side / Counter Domain Brief)

> [!IMPORTANT]
> V7 模式：本文件是 **领域地形知识**，不是执行步骤。
> Cerebrum 读取后应基于第一性原理自主决定分析路径。

## 客户端程序的本质结构

客户端程序（包括安全工具、扫描器、管理端、厚客户端）是一类**信任来自"不可信服务端"的响应数据**的系统。其特征是：

- **主要 Invariant**：客户端只信任来自合法服务端的数据，不允许服务端数据改变客户端的执行路径或访问本地资源。
- **攻击方向反转**：攻击者控制的是**服务端**，向客户端返回精心构造的恶意响应——攻击流量从服务器流向用户。
- **核心状态**：网络响应解析状态、本地文件系统访问状态、UI 渲染状态、配置文件加载状态
- **核心转换**：客户端发起请求 → 服务端返回响应 → 客户端解析并处理响应（这个"处理"是攻击面核心）

## 已知的结构性地形

### 1. 响应解析层（最高价值攻击面）
客户端的解析器是核心入口，攻击者完全控制输入：
- **JSON/XML/YAML 解析**：反序列化恶意构造的对象——Python `pickle`, Java `ObjectInputStream`, PHP `unserialize` 历史案例极多
- **文件格式解析**：接收并本地保存的文件（日志、配置、报告）——路径参数是否由服务端控制？（目录穿越）
- **命令行组装**：客户端将服务端返回的数据拼接进本地执行的命令——命令注入的经典来源

### 2. 本地权限与资源访问
- **配置文件读写**：客户端在本地保存的配置文件路径和格式——是否允许服务端数据修改？
- **临时文件**：扫描结果、缓存数据存储在 `/tmp` 或固定路径——symlink 攻击目标
- **凭证存储**：客户端如何存储 API Key、Token——是否可从响应数据中被提取或重定向？

### 3. 通信信道假设
- **证书验证**：客户端是否严格验证服务端 TLS 证书？是否允许自签名或跳过 hostname 验证？
- **更新机制**：自动更新逻辑是否校验服务端返回的更新包签名？更新 URL 是否可被中间人替换？

## 已知的 Invariant 失效模式

| Invariant 声明 | 常见失效来源 | 攻击者行动 |
|----------------|------------|----------|
| "只执行本地合法命令" | 服务端数据参与命令拼接未净化 | 返回含 `;` `&&` 的恶意字段 |
| "本地文件写入受限目录" | 服务端控制写入路径参数 | 返回 `../../etc/cron.d/shell` |
| "解析数据不执行代码" | 使用不安全的反序列化库 | 返回 gadget chain payload |
| "服务端身份已验证" | 禁用 TLS 校验或接受自签名 | 中间人注入恶意响应 |

## 分析起点建议

从以下问题入手，驱动假设生成：
1. 客户端从网络接收的数据，最终会到达哪些本地敏感操作（文件写、命令执行、eval）？
2. 网络响应中哪些字段被直接用于本地路径构造或命令拼接？
3. 是否存在客户端完全信任服务端指令执行的"远程控制"语义？
