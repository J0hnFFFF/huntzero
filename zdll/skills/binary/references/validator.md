# Binary 验证器 (Validator): 五维度定损：从崩溃到代码执行

> 一个二进制漏洞的发现，不等于一个可利用的漏洞。
> 你的任务是：衡量从"程序崩溃"到"获得 shell"之间的距离。
> 这个距离可能是一步之遥，也可能是天堑。

## 定损框架：Binary 漏洞的五个破坏维度

### 维度一：可利用性（Exploitability）

**核心问题**：这个漏洞能否被稳定利用来获取代码执行？

| 场景 | 可利用性评估 | 评级 |
|------|-----------|------|
| 栈溢出，无 Canary，无 NX，无 ASLR | 直接注入 shellcode 并执行 | Critical |
| 栈溢出，有 Canary，无 NX，有 ASLR | 需要泄露 Canary 和基地址 | High |
| 栈溢出，有 Canary + NX + ASLR + PIE | 需要信息泄露 + ROP | High |
| 堆溢出，可覆盖堆元数据 | 需要堆风水（Heap Feng Shui）| High |
| UAF，可控制重用对象内容 | 需要精确控制堆分配时序 | High |
| 格式化字符串，可读写任意地址 | 直接写 GOT 表或函数指针 | Critical |
| 整数溢出，导致小分配大写入 | 直接利用堆/栈溢出 | High |
| 信息泄露，只能读取内存 | 无法直接执行代码，但为其他漏洞提供信息 | Medium |
| 拒绝服务（DoS），仅导致崩溃 | 无法获取代码执行 | Low |

### 维度二：利用稳定性（Reliability）

**核心问题**：利用成功率是多少？是否受环境因素影响？

| 稳定性 | 描述 | 评级调整 |
|-------|------|---------|
| 100% 稳定 | 每次输入都触发，无随机因素 | 不变 |
| 高（>80%）| 大多数情况成功，偶尔失败 | -0.5 |
| 中（50-80%）| 需要多次尝试，受堆布局影响 | -1 |
| 低（<50%） | 高度依赖内存布局，难以复现 | -1.5 |
| 仅理论可行 | 需要极端条件，实际利用极难 | -2 |

**影响因素**：
- ASLR：每次启动地址不同，需要信息泄露或爆破
- 堆布局：堆分配顺序影响 chunk 位置，需要 Heap Feng Shui
- 线程竞争：多线程环境下 UAF 的时间窗口难以控制
- 输入长度限制：短输入可能无法构造完整 ROP chain

### 维度三：权限提升潜力（Privilege Escalation）

**核心问题**：漏洞被利用后，攻击者获得了什么权限？

| 场景 | 权限评估 | 评级 |
|------|---------|------|
| 远程网络服务漏洞 → 直接获得 shell | 服务账户权限 | Critical |
| SUID 程序漏洞 → 本地提权 | root 权限 | Critical |
| 内核驱动漏洞 → 内核态执行 | ring 0 权限 | Critical+ |
| 普通用户程序漏洞 → 仅当前用户权限 | 无提升 | Medium |
| 沙箱内漏洞 → 沙箱逃逸 | 取决于沙箱强度 | High |

### 维度四：攻击向量可达性（Attack Vector Reachability）

**核心问题**：攻击者需要什么条件才能触发漏洞？

| 向量 | 描述 | 评级调整 |
|------|------|---------|
| 远程网络（无需认证）| 直接发送恶意数据包 | +1 |
| 远程网络（需认证） | 需要有效用户凭证 | 不变 |
| 本地网络 | 需要与目标同一网络 | -0.5 |
| 本地文件 | 需要用户打开恶意文件 | -1 |
| 本地命令行 | 需要本地 shell 访问 | -1.5 |
| 物理访问 | 需要接触设备 | -2 |

### 维度五：修复难度（Remediation Complexity）

**核心问题**：修复这个漏洞需要多少工程成本？

| 难度 | 描述 | 评级调整 |
|------|------|---------|
| 单点修复 | 修改一个函数（如添加长度校验） | -0.5 |
| 多点修复 | 需要在多个函数中添加校验 | 不变 |
| 架构级修复 | 需要重构内存管理或输入处理架构 | +0.5 |
| 依赖升级 | 需要升级第三方库（如 libpng、openssl） | +1 |
| 无法修复 | 硬件缺陷或设计层面问题（如 某已知漏洞） | +2 |

## 专家评估标准

### 场景一：远程网络服务栈溢出

**漏洞**：`recv()` 后 `strcpy()` 到栈缓冲区，无 Canary，NX enabled，ASLR enabled。

**五维度评估**：
- 可利用性：需要信息泄露 + ROP → **High**
- 稳定性：如果存在信息泄露，利用较稳定 → **高（>80%）**
- 权限提升：服务账户权限 → **High**
- 攻击向量：远程无需认证 → **+1**
- 修复难度：单点修复（用 strncpy 替代 strcpy）→ **-0.5**

**综合定损**：**Critical / P0**

**威慑声明**：
> 攻击者只需向目标端口发送一个精心构造的数据包，即可完全控制该网络服务。
> 虽然 NX 和 ASLR 增加了利用难度，但格式化字符串漏洞或信息泄露可轻易绕过这些保护。
> 这是直接面向互联网的服务，攻击门槛极低，影响极大。

### 场景二：SUID 程序栈溢出

**漏洞**：SUID root 程序中 `strcpy()` 溢出，无 Canary，NX disabled。

**五维度评估**：
- 可利用性：直接注入 shellcode，NX disabled → **Critical**
- 稳定性：本地利用，地址固定，100% 稳定 → **100%**
- 权限提升：SUID root → **root 权限（Critical+）**
- 攻击向量：需要本地账户 → **-1.5**
- 修复难度：单点修复 → **-0.5**

**综合定损**：**Critical / P0**

### 场景三：Web 浏览器解析器整数溢出

**漏洞**：图片解析库中 `width * height * 4` 整数溢出，导致小分配大写入。

**五维度评估**：
- 可利用性：堆溢出，需要 Heap Feng Shui → **High**
- 稳定性：堆布局不稳定，成功率中等 → **中（50-80%）**
- 权限提升：浏览器沙箱内，需要沙箱逃逸 → **Medium**
- 攻击向量：诱导用户打开恶意图片 → **-1**
- 修复难度：升级第三方库 → **+1**

**综合定损**：**High / P1**

### 场景四：内核驱动 UAF

**漏洞**：内核模块中 `free(ptr)` 后通过 ioctl 仍可使用 ptr。

**五维度评估**：
- 可利用性：UAF 在内核态，可利用性极高 → **Critical+**
- 稳定性：内核堆布局相对稳定 → **高（>80%）**
- 权限提升：ring 0 执行，完全控制系统 → **Critical+**
- 攻击向量：需要加载驱动或触发特定 ioctl → **-0.5**
- 修复难度：内核代码修复，需重启 → **+1**

**综合定损**：**Critical / P0**
